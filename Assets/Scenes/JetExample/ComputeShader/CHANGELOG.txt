Сцена RoomSmoke — цифровой двойник распространения дыма в помещении
====================================================================
Добавлен сценарий ScenarioType.RoomSmoke (SFUnifiedCS): помещение из двух комнат
с дверным проёмом (penalization-стены + внутренняя перегородка), источник дыма и вытяжка.

Новые силы/механизмы (которых не было):
- AddBuoyancyToVelocity (SFComputeKernelsContainer): плавучесть по Буссинеску
  u += β·χ·dir·dt, пропорциональная концентрации дыма χ (горячий дым поднимается).
  Применяется на поле скорости с последующим PressureProject (несжимаемость сохраняется).
- InjectChiSource / ChiSinkVent: источник (χ→max(χ,value) в маске) и вытяжка
  (χ*=decay в маске) скаляра дыма χ. χ здесь — пассивный носитель концентрации:
  введены флаги CSISF.chiAffectsPsiVacuum / maskVelocityWithChi (для дыма выключены),
  чтобы χ адвектировался, но не «обнулял» ψ и поле скорости вне дыма (среда = весь объём).
- Вытяжка с активным подсосом: ApplyJetBoundary с k, направленным в зону вытяжки
  (втягивающее граничное условие на скорость).
- PushParticlesOutOfSolid / KillParticlesInVent (SFComputeParticlesWall): столкновение
  трассеров с внутренними стенами и удаление трассеров в зоне вытяжки (через CompactParticles).

Геометрия: BuildRoomLayoutMask (внешние стены + перегородка по X минус дверной проём,
минус зоны источника/вытяжки), BuildBoxMask. Пресет SFUnifiedRoomSmokePreset и пункт
меню «ShrodingerFlow/Create Room Smoke Scene» (RoomSmokeCSSceneSetup) с частицами и raymarch.

Drift-flux (всплытие дыма):
- Дым моделируется как χ-«фаза» (как жидкость в контейнере): в воздухе ψ→вакуум и u=0
  (спокойный воздух без FFT-шума), дым (χ≥порога) — несжимаемый поток + плавучесть.
- Маска скорости по χ зануляет поле в воздухе, из-за чего полу-лагранжева адвекция χ не могла
  занести дым в неподвижный воздух (взаимная блокировка). Решено добавлением дрейфа всплытия
  (smoke rises relative to air): к адвекции χ (_ChiDrift* в AdvectLiquidChi) и к трассерам
  (AddBuoyantDriftToParticles, взвешен по χ) добавляется восходящая скорость _roomSmokeRiseSpeed.
  Это физичная drift-flux модель: дым поднимается сквозь спокойный воздух, не «застревая» у источника.

Турбулентная диффузия/дисперсия (султан → клубящееся облако):
- Проблема: маска скорости держит воздух спокойным, поэтому дым шёл строго вверх тонким
  столбом сечением источника (буссинесковский подсос не мог развиться — скорость вокруг
  столба замаскирована в нуль). Добавлены два физичных механизма турбулентного рассеивания:
- DiffuseChi (SFComputeKernelsContainer): диффузия поля χ, χ += alpha·(Σ6 соседей − 6χ),
  alpha = D·dt/h² ∈ [0, 0.16] (явная схема, границы домена зеркальные). Эддивизная
  диффузия дыма — расширяет султан вбок и даёт растекание под потолком и через дверной проём.
- DisperseParticlesInChi (SFComputeParticlesChiConstrain): турбулентная дисперсия трассеров —
  случайное блуждание внутри дыма (амплитуда взвешена по χ), превращает столб трассеров
  в клубящееся облако. Параметры _roomSmokeDiffusion и _roomTracerDispersion в пресете.
- AddCurlNoiseTurbulence (SFComputeKernelsContainer): когерентная вихревая турбулентность —
  к скорости внутри дыма (взвешено по χ) добавляется curl шумового потенциала (бездивергентное
  вихревое поле, value-noise). В отличие от белого шума дисперсии, даёт КОГЕРЕНТНЫЕ вихри:
  дым клубится и вовлекает воздух вбок, султан расширяется и перестаёт быть прямым.
  Анимируется во времени (_CurlTimeOffset — эволюция вихрей). Та же возмущённая скорость
  переносит и χ, и трассеры → согласованное турбулентное движение. Параметры
  _roomTurbAmplitude (амплитуда) и _roomTurbScale (частота вихрей) в пресете.


Аудит ISF Compute Shader — исправления и оптимизации
=====================================================

BUG 1 (КРИТИЧЕСКИЙ): Ненормализованные веса трилинейной интерполяции
---------------------------------------------------------------------
Файл: SFComputeParticles.compute, ядро InterpolateVelocity

Проблема: Веса интерполяции wx, wy, wz лежали в диапазоне [0, dx) вместо [0, 1).
При dx = 0.0625, частица на 80% пути между узлами получала вес 0.05 вместо 0.8.
Интерполяция вырождалась в quasi-nearest-neighbor — частицы двигались грубо
с сеточными артефактами вместо плавных траекторий.

Баг унаследован из оригинального CUDA (update_velocities.cu).

Исправление: wx = (tmp_x - ix * _TorDX) / _TorDX  (аналогично для wy, wz).


BUG 2 (ФИЗИЧЕСКИЙ): AddTurbViscosity вычисляет не то
-----------------------------------------------------
Файл: SFComputeLES.compute, ядро AddTurbViscosity

Проблема: Код вычислял Laplacian(nu_t) (лапласиан самой турбулентной вязкости)
и добавлял одно и то же скалярное значение ко всем трём компонентам скорости.
Стандартная модель Smagorinsky требует nu_t * Laplacian(u_i) — вязкую диффузию
самой скорости. Вместо затухания мелкомасштабных вихрей добавлялся градиент
градиента вязкости — физически бессмысленная операция.

Баг унаследован из оригинального CUDA (add_turb_viscosity.cu).

Исправление: Для каждой компоненты (U, V, W) отдельно вычисляется Laplacian(u_i),
затем применяется dt * nu_t_center * Laplacian(u_i).


BUG 3 (SAFETY): Отсутствие защиты от отрицательных индексов
------------------------------------------------------------
Файл: SFComputeParticles.compute, ядро InterpolateVelocity

Проблема: Если позиция частицы становилась отрицательной (из-за численной ошибки),
floor(pos/dx) давал отрицательный ix. Значение ixp = (ix+1) % Res было обёрнуто,
но сам ix использовался для индексации буфера без проверки — out-of-bounds доступ.

Баг унаследован из оригинального CUDA.

Исправление: Добавлен periodic wrap: ix = ((ix % ResX) + ResX) % ResX
(аналогично для iy, iz).


BUG 4 (MINOR): Подозрительный sign-flip в VelocityOne
------------------------------------------------------
Файл: SFComputeKernels.compute, ядро VelocityOne

Проблема: Когда мнимая часть скалярного произведения близка к нулю,
код выполнял r *= -1 (инверсию знака угла). Физической мотивации нет —
это хак из оригинального CUDA для подавления шума, но он мог инвертировать
скорость на границах вихрей.

Баг унаследован из оригинального CUDA (velocity_one.cu).

Исправление: Заменено на r = 0.0 — обнуление скорости вместо инверсии.


PERF 1: Аллокация временных буферов каждый кадр
------------------------------------------------
Файл: CSParticles.cs, метод AddParticles

Проблема: Каждый вызов AddParticles (каждый кадр) создавал и уничтожал
3 ComputeBuffer — лишняя нагрузка на аллокатор GPU.

Исправление: Staging-буферы (_stagingX/Y/Z) предаллоцированы и переиспользуются.
Расширяются через EnsureStagingCapacity() только если нужен больший размер.
Освобождаются в Dispose().


PERF 2: GPU обрабатывает все частицы, включая вылетевшие
--------------------------------------------------------
Файлы: CSParticles.cs + SFJetCS.cs

Проблема: Счётчик _size только рос. GPU считал RK4 для всех 50000 частиц,
даже если 90% вылетели за пределы объёма.

Исправление: Добавлен метод CompactParticles() — читает позиции с GPU,
отсеивает вылетевшие за пределы частицы, перезаписывает GPU-буферы
компактным списком живых частиц. Вызывается каждые 60 кадров из SFJetCS.
